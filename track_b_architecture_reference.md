# Architecture Reference: Trustless Exam System (Track B - Live Cloud)

This document outlines the production-grade, highly scalable cloud architecture for the Trustless Exam System. It bridges Web3 immutability (Solana) with Web2 scalability and AI capabilities (AWS).

## 1. System Overview

The system ensures zero-trust at every stage of the examination process:

1. **No paper leaks:** Question papers are encrypted using AWS KMS, and the decryption key is only released when a Solana smart contract verifies a multisig quorum (e.g., 3 out of 5 examiners).
2. **No answer tampering:** Student answers are stored in AWS, but their cryptographic hashes are anchored to the Solana blockchain.
3. **Transparent grading:** Amazon Bedrock evaluates subjective answers, and the final scores (with AI justifications) are immutably logged on-chain.

## 2. Technology Stack

- **Frontend:** Next.js (App Router), Tailwind CSS, `@solana/wallet-adapter-react`. Hosted on **AWS Amplify**.
- **Blockchain (Trust Layer):** Solana Devnet/Mainnet, Anchor Framework (Rust).
- **Backend (Scale Layer):** Node.js/TypeScript running on **AWS Lambda** (via API Gateway) or **NestJS** deployed on AWS App Runner.
- **Storage & Database:** **Amazon S3** (Encrypted PDFs/Blobs), **Amazon DynamoDB** (High-throughput session data, user mapping).
- **Security & Auth:** **AWS KMS** (Asymmetric Encryption), **Amazon Cognito** (Web2 Auth linked to Web3 Wallet).
- **AI & Orchestration:** **Amazon Bedrock** (Claude 3.5 Sonnet), **AWS Step Functions** (Grading pipelines).

## 3. Core Architecture Workflows

### Phase A: Exam Creation & Encryption (Pre-Exam)

1. **Upload:** The Exam Admin uploads the question paper (PDF/Text) via the Next.js frontend.
2. **Encrypt:** The backend encrypts the file using a unique Data Key generated by **AWS KMS**.
3. **Store Data:** The encrypted file is saved to **Amazon S3**.
4. **Anchor State:** The backend calls the Solana Anchor program (`initialize_exam`) to create an `ExamState` account. This account stores:
   - The S3 URI of the encrypted paper.
   - The expected Multisig threshold (e.g., 3/5).
   - The exam status (`is_live: false`).

### Phase B: Multisig Decryption & Exam Unlock (The "Zero-Leak" Guarantee)

1. **Multisig Approval:** Appointed examiners connect their Phantom/Backpack wallets and sign an `approve_exam` transaction on Solana.
2. **State Change:** Once the threshold is met, the Solana `ExamState` flips to `is_live: true`.
3. **Event Listener:** An AWS Lambda function polling the Solana RPC (or triggered by a webhook) detects this state change.
4. **Key Release:** Only upon verifying the on-chain `is_live` state, the Lambda function authorizes AWS KMS to decrypt the data key and securely distribute it to authenticated, registered students via the API.

### Phase C: Exam Execution & Answer Submission

1. **Local Decryption:** The student's frontend pulls the encrypted S3 file and decrypts it in-memory using the provided key.
2. **Answering:** The student completes the exam.
3. **Submission:**
   - The Next.js app sends the raw JSON answers to an **API Gateway -> Lambda** endpoint.
   - Lambda saves the answers to **DynamoDB** and uploads large attachments to **S3**.
   - Lambda generates a **SHA-256 Hash** of the exact database record and returns it to the frontend.
4. **Blockchain Commitment:** The Next.js frontend prompts the student to sign a Solana transaction containing this SHA-256 hash. The Anchor program logs this hash permanently under the student's `AnswerSheet` account.
   - _Security Note: If a database admin alters the answers in DynamoDB later, the hash of the altered record will not match the hash signed by the student on Solana._

### Phase D: AI Grading Pipeline (Post-Exam)

1. **Orchestration:** Once the exam window closes, an **AWS Step Function** is triggered.
2. **Batch Processing:** The Step Function pulls batches of student answers from DynamoDB.
3. **AI Evaluation:** For each answer, a Lambda function calls **Amazon Bedrock** (Claude 3.5 Sonnet).
   - _Strict Schema:_ Bedrock is instructed via the Converse API (`toolSpec.strict: true`) to return a guaranteed JSON structure containing: `score`, `rubric_match`, and `justification`.
4. **Update DB:** The grading results are saved back to DynamoDB.
5. **Final Immutability:** A final backend wallet signs a transaction anchoring the `EvaluationHash` (Hash of the AI's grade and justification) back to the student's Solana account.

## 4. Key Security & Architecture Decisions

- **Why not store exams on-chain?** Blockchains are expensive and slow for large data (like PDFs). AWS S3 provides cheap, scalable storage, while Solana provides the lightweight, immutable proof (the hash).
- **Why use AWS KMS?** If decryption keys are hardcoded in a database, a compromised server leaks the exam. By tying KMS decryption policies strictly to the Solana multisig state, human error and centralized database hacks are completely bypassed.
- **Why AWS Step Functions for AI?** Grading hundreds of exams via LLMs can hit rate limits or timeout standard HTTP requests. Step Functions handle retries, rate limiting, and parallel processing flawlessly.
